# 0006 前缀缓存是一等公民,用量按各家口径记

- 状态:已接受;10-15 三种协议的缓存逐项对照 pi 补齐(见 `docs/llm.md` 第十一节"流失败与前缀缓存")
- 日期:2026-07-16;08-26 用量四元化;10-08 Anthropic 缓存断点;10-15 对照 pi
- 提交:`6887250da`、`d6af760ec`、`8cdf34daf`、`37079cd36`、`e2c06fe1b`

## 背景

智能体每一轮都要把系统提示(工具表、操作说明、人设、技能表)整段重发。坐标、时间这些每刻在变的东西原来拼在系统提示中段,
每轮都把厂家的前缀缓存打碎,花费按全价算。

## 决定

- **系统提示字节级稳定:** 世界状态(`<env>`、`<known_blocks>`)挪进用户回合,随这一回合的用户消息注入一次,工具链的后续请求复用。
  系统提示因此从第二轮起整段命中缓存。
- **用量按各家口径折算:** 用量帧的字段名和缓存折扣是各家方言,由适配器自己解(`LlmProvider.usage`)。
  后来统一成四元:输入、输出、缓存读、缓存写,外加命中率。
- **Anthropic 显式打缓存断点(10-08):** 它不会自动缓存,要在请求里标出断点。位置:最后一个工具、system、消息里最后两个可放的块
  (比 pi 多一个,因为每轮末尾追加的 `<runtime_state>` 下一轮就变,倒数第二块才是历史末尾);缓存存活 5 分钟,不提供 1h 选项。
- **其余协议同样要把缓存做对(10-15):** OpenRouter 上的 `anthropic/*` 型号走 Chat 也要显式断点(位置同上);Responses 传 `prompt_cache_key`
  (同伴 UUID);三种协议的缓存读写都按各家字段记进四元,Anthropic 不再先归一成 OpenAI 的字段名。
- 不记金额:价格随厂家、中转站、订阅制千差万别。

## 后果

- 支持缓存的厂家,重复上下文不再按全价算;`/usage` 能看出缓存有没有被打碎。
- 以后任何往系统提示里塞"会变的东西"的改动,都要先想会不会打碎缓存。`CachePrefixTest` 守着:同一段对话多走一步,工具表、系统提示、已有消息不变样。
